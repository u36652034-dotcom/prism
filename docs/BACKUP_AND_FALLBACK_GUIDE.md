# Prism: Backup, Restore & Automatic Fallback Features\n\n## Overview\n\nThis document describes three new powerful features added to Prism that solve critical production issues:\n\n1. **Export/Import Providers** - Backup and restore your upstream provider credentials\n2. **Automatic Fallback Chain** - Intelligent retry logic when providers fail\n3. **Provider Health Monitoring** - Track provider status and cooldown cycles\n\n---\n\n## Feature 1: Export/Import Providers\n\n### Problem Solved\n- ❌ No way to backup 10+ providers you've manually configured\n- ❌ Credentials lost on redeploy\n- ❌ Manual re-entry of all providers required after updating code\n\n### Solution\nAll provider configurations (with credentials) can now be exported and imported safely.\n\n### API Endpoints\n\n#### Export All Providers\n```bash\nGET /api/backup/export\n\n# Returns:\n{\n  \"success\": true,\n  \"message\": \"Exported 10 providers\",\n  \"backup\": {\n    \"version\": \"1.0\",\n    \"exportedAt\": \"2026-09-14T16:30:00Z\",\n    \"providerCount\": 10,\n    \"providers\": [\n      {\n        \"id\": \"upstream_1234567_abc123\",\n        \"name\": \"OpenAI GPT-4\",\n        \"provider_type\": \"cf_ai_gateway\",\n        \"cf_aig_provider\": \"openai\",\n        \"api_protocol\": \"openai\",\n        \"base_url\": \"https://api.openai.com\",\n        \"api_key\": \"sk-proj-...\",\n        \"available_models\": [\"gpt-4o\", \"gpt-4o-mini\"],\n        \"created_at\": 1694704200000\n      },\n      // ... more providers\n    ],\n    \"checksum\": \"abcd1234efgh5678ijkl9012mnop3456\"\n  }\n}\n```\n\n#### Export as Base64 File (for download)\n```bash\nGET /api/backup/export-download\n\n# Returns base64-encoded JSON file\n# Browser will download as: prism-backup-2026-09-14.json.b64\n```\n\n**How to use:**\n1. Click \"Export Backup\" in Prism dashboard\n2. Save the downloaded file safely (e.g., in encrypted storage, password manager, etc.)\n3. Keep it as insurance before redeploying\n\n#### Import Providers from JSON\n```bash\nPOST /api/backup/import\nContent-Type: application/json\n\n{\n  \"backup\": { /* BackupExport object from export */ },\n  \"overwrite\": false,\n  \"skipDuplicates\": true\n}\n\n# Returns:\n{\n  \"success\": true,\n  \"imported\": 10,\n  \"skipped\": 0,\n  \"errors\": [],\n  \"message\": \"Imported 10 providers, skipped 0, 0 errors\"\n}\n```\n\n**Options:**\n- `overwrite: false` (default) - Skip if provider already exists\n- `overwrite: true` - Replace existing providers with backup versions\n- `skipDuplicates: true` (default) - Silently skip duplicates\n- `skipDuplicates: false` - Return error for duplicates\n\n#### Import from Base64 File\n```bash\nPOST /api/backup/import-base64\nContent-Type: application/json\n\n{\n  \"backupBase64\": \"eyJiYWNrdXAiOiAuLi59\",  // Base64-encoded backup\n  \"overwrite\": false\n}\n\n# Returns import result (same as above)\n```\n\n**How to use:**\n1. Upload your backup file in Prism dashboard\n2. Click \"Import\" with your desired options\n3. All providers restored instantly\n\n### Data Security\n✅ **Checksum validation** - Detects corrupted backup files\n✅ **Full credentials included** - Don't worry about losing API keys\n✅ **No encryption required** - Use password-protected storage instead\n✅ **Version control** - Backup file includes version for future compatibility\n\n---\n\n## Feature 2 & 3: Automatic Fallback Chain + Health Monitoring\n\n### Problem Solved\n- ❌ When a provider fails (rate limit, auth error, server error), request fails immediately\n- ❌ No automatic retry to next provider\n- ❌ No way to know provider status\n\n### Solution\nWhen a model request fails, Prism automatically tries the next available provider in the chain.\n\n### How It Works\n\n#### 1. Provider Chain Lookup\nWhen you request a model (e.g., `gpt-4o`):\n```\n1. Prism finds ALL upstreams that support this model\n2. Sorts by health: healthy → cooldown → disabled\n3. Tries each in order until one succeeds\n```\n\n#### 2. Failure Handling\n\n**Auth Errors (401, 403):**\n```\n→ Provider DISABLED permanently\n→ Reason: Invalid/expired API key\n→ No more attempts to this provider (until reset)\n```\n\n**Rate Limits (429):**\n```\n→ Provider goes to COOLDOWN\n→ Cooldown duration: 5 min (1st failure) → 10 min → 30 min (progressive backoff)\n→ Automatically recovered after cooldown expires\n```\n\n**Server Errors (5xx):**\n```\n→ Provider goes to COOLDOWN (same as 429)\n→ Automatically retries after cooldown\n```\n\n**Client Errors (4xx, except 429):**\n```\n→ Error returned to user\n→ No retry to other providers (not a provider issue)\n```\n\n#### 3. Success Recovery\n```\nWhen a request succeeds:\n→ Provider status set to HEALTHY\n→ Failure count reset to 0\n→ Back to first-choice priority\n```\n\n### API Endpoints\n\n#### Get Provider Health Status\n```bash\nGET /api/backup/health\n\n# Returns:\n{\n  \"success\": true,\n  \"timestamp\": \"2026-09-14T16:30:00Z\",\n  \"totalProviders\": 10,\n  \"healthyCount\": 8,\n  \"cooldownCount\": 1,\n object\n- `exportAsBase64()` - Encode as base64 for safe transmission\n- `importProviders()` - Import from backup JSON with conflict handling\n- `decodeBackupFile()` - Decode base64 backup file\n- `generateChecksum()` - SHA256 validation for data integrity\n\n#### FallbackService (`apps/gateway/src/services/fallback.service.ts`)\n- `getProviderChainForModel()` - Get sorted list of providers for a model\n- `recordProviderFailure()` - Mark provider as failed with status code analysis\n- `recordProviderSuccess()` - Recover provider from cooldown\n- `getProviderHealth()` - Get health of specific provider\n- `getAllHealthStatus()` - Get health of all providers\n- `isErrorRetryable()` - Determine if error should trigger fallback\n- `resetAllHealth()` - Clear all health data\n\n### Data Persistence\n\n✅ **D1 Database (Persistent)**\n- Upstream configurations with API keys\n- Candidate keys and logs\n- Settings\n- Survives redeploys automatically!\n\n⚠️ **In-Memory Health Map (Per-Session)**\n- Provider failure counts\n- Cooldown timers\n- Resets when Worker cold-starts\n- Rebuilt from subsequent requests\n\n### Fallback Flow in proxy.ts\n\n```typescript\n// Before (no fallback):\nconst config = await upstreamService.findConfigForModel(modelName);\nif (!config) return error;\nreturn await fetchFromUpstream(config);  // ❌ Fails if provider errors\n\n// After (with fallback):\nconst chain = await fallbackService.getProviderChainForModel(modelName);\nfor (const provider of chain) {\n  try {\n    const response = await fetchFromUpstream(provider);\n    if (response.ok) {\n      fallbackService.recordProviderSuccess(provider.id);\n      return response;  // ✅ Success!\n    }\n    if (!fallbackService.isErrorRetryable(response.status)) {\n      fallbackService.recordProviderFailure(provider.id, response.status);\n      continue;  // Try next provider\n    }\n  } catch (err) {\n    fallbackService.recordProviderFailure(provider.id, 503, err.message);\n    continue;  // Try next provider\n  }\n}\nreturn \"All providers failed\";\n```\n\n---\n\n## Testing\n\n### Test Export/Import\n```bash\n# 1. D1 database persists across redeploys. But we recommend exporting a backup first as insurance.\n\n**Q: Can I export credentials?**\nA: Yes! Export includes raw API keys. Store safely (encrypted cloud storage, password manager, etc.)\n\n**Q: How long do providers stay in cooldown?**\nA: Progressive backoff: 5 min → 10 min → 30 min. Automatically recovered after timeout.\n\n**Q: What if all providers fail?**\nA: User gets `HTTP 503` with list of attempted providers and their error codes.\n\n**Q: Can I disable the fallback feature?**\nA: Yes, comment out the `proxyAndAuditRequestWithFallback` calls and use original `proxyAndAuditRequest`.\n\n**Q: Does fallback work across protocols (OpenAI ↔ Anthropic)?**\nA: Currently same-protocol only. Cross-protocol fallback coming soon.\n\n---\n\n## Migration Guide\n\n### For Existing Prism Deployments\n\n1. **Backup first:**\n   ```bash\n   # Export your current providers\n   GET /api/backup/export\n   # Save the JSON file\n   ```\n\n2. **Merge this branch:**\n   ```bash\n   git merge origin/feature/export-import-fallback\n   ```\n\n3. **Deploy:**\n   ```bash\n   pnpm deploy\n   # No schema changes needed - D1 untouched\n   ```\n\n4. **Verify:**\n   ```bash\n   # Check that providers still exist\n   GET /api/upstreams\n   # Check health\n   GET /api/backup/health\n   ```\n\n5. **Update proxy.ts** (if using fallback):\n   - Replace imports: `import { proxyAndAuditRequestWithFallback } from './proxy-fallback'`\n   - Use new function in route handlers\n\n---\n\n## Future Enhancements\n\n- [ ] Cross-protocol fallback (OpenAI request → Anthropic provider)\n- [ ] Cost-optimized routing (cheaper provider first)\n- [ ] Model-level SLA monitoring\n- [ ] Prometheus metrics export\n- [ ] Scheduled provider health probes\n- [ ] Dashboard UI for health visualization\n- [ ] Automatic provider re-ranking by success rate\n\n---\n\n## Support\n\nFor issues or questions:\n1.
